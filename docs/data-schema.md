# 数据口径 & 蒲公英资源库搭建方案

## 一、`data/data-full.json` 结构

```jsonc
{
  "meta": {
    "keys": [/* 24 个字段名，records 里每条达人按这个顺序存数组 */],
    "industries": [/* 16 大行业，顺序即 vmask 位序 */],
    "identity": ["素人", "达人", "MCN机构", "品牌合作人"],
    "persona": [/* 6 类人设 */],
    "dim": [/* 6 类内容维度 */],
    "tier": [/* 7 档粉丝量级 */],
    "crowd_list": [/* 8 大人群 */],
    "age_list": [/* 5 档年龄 */],
    "unit": "per-mille（除以 1000 即比例）",
    "total": 2000,
    "source": "小红书蒲公英（示例数据）"
  },
  "total": 2000,
  "records": [[/* 每条达人一个数组 */], ...]
}
```

### 24 个字段（`meta.keys` 顺序）

| # | key | 含义 | 来源（蒲公英/小红书） |
|---|-----|------|----------------------|
| 0 | id | 蒲公英博主 ID | 蒲公英后台博主列表 |
| 1 | name | 昵称 | 蒲公英后台 |
| 2 | ide | 身份下标（identity） | 后台「身份」字段 |
| 3 | mcn | MCN 名称 | 后台「MCN」 |
| 4 | per | 人设下标（persona） | 运营打标 |
| 5 | dim | 内容维度下标（dim） | 运营打标 |
| 6 | tier | 粉丝量级下标（tier） | 由粉丝数分档 |
| 7 | tag | 一级内容标签 | 后台「内容垂类」 |
| 8 | vmask | 16 行业垂类位掩码 | 由 tag 经映射打标 |
| 9 | male | 男粉占比（‰） | 蒲公英博主画像 |
| 10 | female | 女粉占比（‰） | 蒲公英博主画像 |
| 11 | age | 5 档年龄分布（‰，数组） | 蒲公英博主画像 |
| 12 | city | 城市分布（[城市,‰] 平铺数组） | 蒲公英博主画像 |
| 13 | crowd | 8 大人群分布（‰，数组） | 蒲公英博主画像/人群包 |
| 14 | ios | iPhone 占比（‰） | 画像（可选，无则补 0） |
| 15 | p_img | 图文笔记报价（元） | 蒲公英刊例 |
| 16 | p_video | 视频笔记报价（元） | 蒲公英刊例 |
| 17 | c_img | 图文 CPE（元/互动） | 由报价÷互动量估算 |
| 18 | c_video | 视频 CPE（元/互动） | 由报价÷互动量估算 |
| 19 | eng | 互动率（‰） | 近 30 天笔记互动/曝光 |
| 20 | notes30 | 近 30 天笔记数 | 蒲公英后台 |
| 21 | fans | 粉丝数 | 蒲公英后台 |
| 22 | home_url | 小红书主页 | 后台 |
| 23 | pgy_url | 蒲公英主页 | 后台 |

> 画像类数值统一用「千分位」存整数，前端除以 1000 得到比例，比存小数更省体积。

## 二、`data/insights.json` 结构

每个行业一个 key（外加 `__all__` 平台整体），用于洞察面板和报告：

```jsonc
{
  "美妆个护": {
    "hot_trends": ["...", "..."],      // 行业热点（运营/爬虫整理）
    "topic_ideas": ["...", "..."],     // 选题建议
    "strategy": "...",                  // 投放策略话术
    "stats": { "total": 181, "top_persona": [...], "tier_dist": [...],
               "crowd_dist": {...}, "age_dist": {...}, "top_cities": {...} }
  },
  "__all__": { ... }
}
```

`stats` 可离线算好；`hot_trends/topic_ideas/strategy` 建议用「平台热点抓取 + 模板」半自动生成，避免纯手写过期。

## 三、蒲公英资源库怎么建立（对照星图版）

星图版是「精选达人刊例总表 → 画像接口 → I列标签打垂类 → 打包 json」。蒲公英版建议同样四步：

1. **导出博主刊例**：从蒲公英后台导出全量/精选博主表，拿到 ID、昵称、身份、MCN、粉丝数、图文/视频报价、内容垂类标签、近 30 天数据。
2. **补画像**：用蒲公英后台的博主画像页/开放能力补男女、年龄、城市、人群包、iPhone 占比；互动率、笔记数取近 30 天。
3. **打垂类**：按 `js/config.js` 的 `VERTICAL_TAG_MAP` 把「一级内容标签」映射到 16 大行业，生成 `vmask` 位掩码（一个博主可命中多行业）。
4. **算 CPE 与洞察**：CPE = 报价 ÷ 预估互动量；`insights.json` 的 stats 从主库聚合，趋势/选题另配。

### 与星图版的关键差异（为什么更适合小红书）

| 维度 | 星图版（抖音） | 蒲公英版（小红书） |
|------|--------------|------------------|
| 内容形态 | 视频时长 1-20s/21-60s/61-120s | 图文 / 视频 两档报价 |
| 核心指标 | CPM | CPE（互动成本）+ 互动率 |
| 画像重心 | 八大人群 + 城市 | 八大人群 + 城市 + iPhone/华为 + 年龄 |
| 数据体量 | ~3 万 | 可先按精选池，后续全量 |

## 四、打分模型（`js/match.js`）

- 硬过滤：身份 / 粉丝量级 / 人设 / 内容维度 / 预算区间 / 昵称搜索 / 仅垂类。
- 软打分（权重见 `js/config.js` 的 `MATCH_WEIGHTS`）：
  - `vertical` 行业垂类（0.28）：命中垂类=1，非垂类=0.25，未选行业=0.6。
  - `audience` 人群/年龄/城市覆盖度（0.24）：所选标签在博主画像中的占比均值，未选=0.5。
  - `gender` 性别偏好（0.06）：对应性别占比，未选=0.5。
  - `engagement` 互动率百分位（0.18）：相对全池的百分位，越高越好。
  - `activity` 近 30 天更新百分位（0.08）。
  - `cpe` 性价比（0.16）：CPE 越低得分越高（1 − CPE 百分位）。
- 最终 `score = round(100 × Σ(权重×维度分))`，输出 1~99，并附 Top 理由。

这个模型比星图版「55 分起步 + 固定加分」更稳定：所有维度归一化，且权重可集中校准。
